分層職責

  • Controller: 負責 Request 映射、參數校驗與 HTTP 回應。
  • Service: 核心業務邏輯，包含事務 (Transaction) 邊界。

4. 分散式事務：Seata TCC 框架流程

Data Consistency

在複雜的微服務調用中，如何透過 TCC 模型確保各節點間的數據達成最終一致性。

sequenceDiagram participant Coordinator as Seata Manager (TC) participant Action as TCC Action (Try-Confirm-Cancel) Coordinator->>Action: [第一階段: Try] 預留資源 (檢查庫存/凍結資金) alt 成功 Coordinator->>Action: [第二階段: Confirm] 真正的業務提交 else 失敗 Coordinator->>Action: [第二階段: Cancel] 釋放預留資源 (回滾) end
  • Try: 完成所有業務檢查，預留必要的業務資源。
  • Confirm: 不再做檢查，直接提交業務，必須保證冪等。
  • Cancel: 回放 Try 階段預留的資源，必須保證冪等。

5. 高效通訊：gRPC 通訊框架

Internal Performance

使用二進制序列化 (Protobuf) 取代 JSON，極大化服務間通訊效能並減少額外頻寬損耗。

Protobuf 定義

service BookService {
  rpc GetBook(BookRequest) 
    returns (BookResponse);
}
message BookResponse {
  int32 id = 1;
  string title = 2;
  bool is_borrowed = 3;
}

通訊優勢

  • 格式更小: 二進制封裝，比 JSON 小 70% 以上。
  • 速度更快: 編解碼效能優於標準 REST。
  • 強型別介面: 原生 IDL 確保服務間契約不破壞。
