Spring Boot 高階技術百科：究極全紀錄

1. 專案根基與極致技術選型

FOUNDATION

本專案嚴格遵循「內容只增不減」的擴充原則。本章節彙整了從基礎單機核心到微服務體系的所有技術細節。

全方位技術棧清單

Java 21 (LTS) Spring Boot 3.2.2 Spring Cloud Gateway MVC JPA / Hibernate 6 QueryDSL / MapStruct gRPC / Protobuf 3 Apache Kafka 3.x Seata 2.0 (TCC) WebSocket (STOMP) Redis Cache H2 / MySQL / PostgreSQL
技術維度 選型版本 技術目的與價值
核心引擎 Spring Boot 3.2.2 支撐 Java 21 虛擬緒，實現高性能併發。
存取層 JPA / Hibernate 標準化 ORM 映射，保證數據處理的一致性。
消息隊列 Apache Kafka 實現系統間完全解耦，支持高吞吐訊息流。
分散式事務 Seata TCC 解決跨微服務操作的原子性問題。
通訊協定 gRPC / HTTP 2.0 利用二進制序列化極大化內部 call 效率。

環境部署檢核清單

💡 啟動前環境 Ready Check：
  1. JDK 21: 確認 java -version 為 21+。
  2. Infrastructure: 啟動 Docker 並執行 Kafka (29092) 與 Redis (6379)。
  3. Persistence: 預設 H2 Console 位址於 /h2-console。

核心配置參數深度剖析 (Properties)

# Kafka 性能調優
spring.kafka.producer.batch-size=16384     # 每批次最大 Bytes
spring.kafka.producer.properties.linger.ms=5 # 減少發送次數，提高吞吐
spring.kafka.producer.compression-type=snappy # 高效壓縮

# Seata & 微服務
seata.tx-service-group=default_group
spring.cloud.discovery.enabled=false # 本地開發模式

gRPC 介面定義 (Proto Specs)

利用 Protobuf 明確定義服務契約，避免因 JSON 欄位變更導致的不可預期錯誤。

service BookService {
    // 高效能二進制 RPC 呼叫
    rpc GetBook(BookRequest) returns (BookResponse);
}
message BookRequest { int32 id = 1; }
message BookResponse { 
    int32 id = 1; string title = 2; string author = 3; 
}

微服務通訊解決方案全矩陣

通訊手段 底層協定 序列化方式 核心優點
REST API HTTP/1.1 JSON (字串) 標準化、易於前端調試。

stateDiagram-v2 [*] --> App: 產生事件 (如訂單建立) App --> KafkaProducer: CompletableFuture.send() KafkaProducer --> Buffer: 內存緩存 (Linger 5ms) Buffer --> Network: Snappy 壓縮發送 Network --> Broker: 寫入 Topic (Partition) Broker --> Consumer: 訂閱者監聽觸發 (Listener) Consumer --> WebSocket: 即時更新前端看板 WebSocket --> [*]

Seata TCC 分散式事務全生命週期

sequenceDiagram participant TC as 事務協調器 participant T as Try (準備) participant C as Confirm (確定) participant R as Cancel (回滾) TC->>T: 1. 執行 prepare() (凍結餘額/預留庫存) alt 所有 Try 成功 TC->>C: 2. 執行 commit() (真正扣除資源) else 任何一個失敗 TC->>R: 2. 執行 rollback() (釋放預留資源) end

究極疑難排查清單

🚨 專業排查紅區：
  • 測試 Bean 注入衝突? 請在測試類標註 properties = "seata.enabled=false"。
  • Kafka 無法消費? 確認 group-id 有效且 Topic 已經啟動。
