1. CI/CD 自動化建置與測試流水線

Continuous Integration

確保每一行進入分支的代碼都經過嚴格的質量檢核。本專案透過自動化流水線實現「快速交付、質量保證」。

graph LR A[Developer Push] --> B[GitHub Actions/Jenkins Trigger] B --> C{Build & Compile} C -->|Success| D[Unit Tests - JUnit 5] C -->|Failure| Error[Notify Dev] D --> E[Integration Tests - Seata/Kafka] E --> F[Static Analysis - SonarQube] F --> G[Artifact Storage - JAR/Docker] style B fill:#dcfce7 style G fill:#22c55e,color:#fff
關鍵流水線步驟：
1
檢核編譯：確保代碼符合 Java 21 語法與相依性正確。
2
自動化測試：執行超過 50+ 個測試案例，包含 MockMvc 與 EmbeddedKafka。
3
質量門檻：檢測環複雜度、潛在 Bug 與測試覆蓋率。

2. 容器化與運維佈署流水線 (DevOps)

Continuous Deployment

基於雲原生理念，將應用程式容器化，實現跨環境的一致性部署。

graph TD JAR[Fat JAR File] --> Build[Docker Build] Build --> Push[Docker Registry - Docker Hub/Harbor] Push --> Deploy[Kubernetes / Docker Compose] Deploy --> Health{Health Check} Health -->|UP| Running[Production Live] Health -->|DOWN| Rollback[Auto Rollback] style Build fill:#3b82f6,color:#fff style Running fill:#22c55e,color:#fff

3. 數據處理流水線 (Data Processing Pipeline)

Stream Processing

利用 Kafka 高吞吐特性，建構反應式數據處理鏈，實現從數據輸入到最後通知的完整 Pipeline。

graph LR Ingest[API Ingestion] --> Topic[Kafka Inbound Topic] Topic --> Filter[Stream Processor / Filter] Filter --> Enrich[Data Enrichment / JPA] Enrich --> Output[Outbound Topic] Output --> Notify[WebSocket / Email / SMS] style Topic fill:#ea580c,color:#fff style Notify fill:#9333ea,color:#fff
流水線特性：
  • 線性擴展：可增加 Consumer 節點加速處理速度。
  • 重放能力：當後端失效時，可從特定的 Offset 重新執行數據流水線。

4. 監控與指標觀測流水線

Observability
