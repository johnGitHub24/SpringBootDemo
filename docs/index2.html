4. 分散式事務：Seata TCC 框架流程

Distributed Consistency

在微服務環境下，透過 TCC (Try-Confirm-Cancel) 模型確保業務操作的最終一致性。

TCC 執行三階段流程圖

sequenceDiagram participant TC as 事務管理器 (TC) participant Service as 業務服務 (TCC Action) TC->>Service: [Phase 1: Try] 資源預留與凍結 alt 全部 Try 成功 TC->>Service: [Phase 2: Confirm] 正式提交與資源扣除 else 任一 Try 失敗 TC->>Service: [Phase 2: Cancel] 資源釋放 (沖正) end
  • Try：初步檢查資源，完成業務所需的資源預留。
  • Confirm：不做任何檢查，僅執行真正的業務提交，需具備冪等性。
  • Cancel：釋放 Try 階段預留的資源，需具備冪等性。

5. 高效通訊：gRPC 通訊框架

Binary High Performance

利用 HTTP/2 與 Protobuf 二進制序列化，提供比傳統 REST (JSON) 更快速且安全的內部服務通訊。

通訊模型與範例

// book_service.proto 範例
service BookService {
    // 定義強型別服務規紉
    rpc GetBook(BookRequest) returns (BookResponse);
}

message BookResponse {
    int32 id = 1;         // 二進制欄位標記，效率極高
    string title = 2;
    bool is_borrowed = 3;
}
graph LR Client[調用方 Client] -- "二進制流 (Binary Stream)" --> Server[gRPC Server] Server -- "Protobuf 反序列化" --> Logic[業務邏輯處理] Logic -- "二進制回傳" --> Client
gRPC 優勢：
  • 頻寬節省：二進制格式遠小於 JSON 字串。
  • 解析效能：Protobuf 的編碼解碼速度極快。
  • 雙向串流：原生支援 HTTP/2 雙向通訊。
