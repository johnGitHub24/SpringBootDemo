# Claude AI 提示詞實戰：從模糊到精確的迭代詳解

好的提示詞不是一次寫成的，而是透過對需求的不斷精練所得到的。本案例展示如何將一個簡單的「代碼優化要求」演進為一個「完美的開發指令」。

---

## 案例背景
**需求：** 我有一段 Java 代碼，運行很慢，我想要優化它，並增加單元測試。

### 階段 1：初學者提示詞 (模糊不清)
> **Prompt:** 「幫我優化這段代碼，還有幫我寫測試。」
>
> **結果評論：** 
> - Claude 可能會優化性能，但也可能只是改改變數名稱。
> - 測試程式碼可能沒有涵蓋邊界情況。
> - 生成的結果可能缺乏解釋。

---

### 階段 2：進階提示詞 (增加明確任務)
> **Prompt:** 「請分析這段 Java 代碼的性能瓶頸。使用更有效率的數據結構進行重構，並使用 JUnit 5 撰寫測試案例。」
>
> **過程解釋：** 
> 1. **指定技術棧：** 明確提及「Java」與「JUnit 5」，避免生成不兼容的測試。
> 2. **任務拆解：** 將「優化」細化為「分析瓶頸」與「更換數據結構」。

---

### 階段 3：大師級提示詞 (結構化與限制)
與其使用一段文字，我們使用 **XML 標籤** 來區隔指令、背景與約束。

> **Prompt:**
> ```xml
> <role>你是具備高性能運算經驗的資深 Java 工程師。</role>
>
> <context>
> 我目前有一個處理大量訂單數據的列表循環，疑似發生 O(n²) 的性能問題。
> </context>
>
> <task>
> 1. 將以下代碼優化至 O(n) 時間複雜度。
> 2. 生成 3 個單元測試：包含一般場景、邊界場景、空值處理。
> 3. 對優化部分提供簡短的技術原理解釋。
> </task>
>
> <constraints>
> - 僅使用 JDK 21 標準庫，不可引用外部自定義依賴。
> - 變數命名需完全符合 Google Java Style Guide。
> - 輸出使用繁體中文註解。
> </constraints>
>
> <code_to_fix>
> [貼上你的原始代碼]
> </code_to_fix>
> ```

---

## 過程解釋總結：為什麼這樣更有效？

1.  **分離上下文與代碼：** 使用像 `<code_to_fix>` 這樣的標籤，Claude 能精確區分哪裡是你的解釋，哪裡是需要修改的內容。
2.  **減少幻覺 (Hallucination)：** 透過 `<constraints>`，限制了 Claude 亂拉第三方庫的行為。
3.  **引導推理路徑：** 透過這類分步任務，Claude 會先在大腦中進行分析，再輸出代碼，其質量遠高於直接生成。
4.  **一致性：** 指定命名規範（如 Google Style）確保生成代碼的風格與專案一致。
